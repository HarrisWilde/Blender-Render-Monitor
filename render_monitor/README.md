# Render Monitor 渲染监视器（Blender 插件）

类似 KeyShot 的 Render Monitor：把当前场景的状态保存为**快照**，然后按列表
逐个**批量渲染**到指定目录。渲染在**独立子进程**中后台执行，UI 完全不冻结，
且主场景从头到尾零修改。

**当前版本：v1.4.6**

## 功能

每个快照记录：

| 类别 | 内容 |
| --- | --- |
| 物体状态 | 隐藏/显示（`hide_viewport` / `hide_render` / `hide_select`）、位移/旋转/缩放（对象直接数据 `location` / `rotation`（Euler/Quaternion/AxisAngle） / `scale`，含父子层级与 delta 变换；不依赖依赖图评估，exclude/隐藏集合中的对象也可靠）、逐对象渲染可见性（`visible_camera` / `visible_shadow` / `visible_glossy` / `visible_diffuse` / `visible_transmission` 等）、灯光能量/颜色/阴影开关 |
| 集合开关 | 集合数据级：视口隐藏/渲染排除（`hide_viewport` / `hide_render`）；**视图层级开关**：outliner 里集合左侧的勾选框（`exclude`，点灭即排除）和眼睛图标（`hide_viewport`），逐 View Layer 记录 |
| 环境 | **World 的切换**（`scene.world` 指向哪个 World）+ 背景色、Background 节点颜色/强度 |
| 相机 | 当前活动相机（按名称引用，渲染时切换） |
| 渲染设置 | 引擎、分辨率、帧率、输出格式（PNG/EXR/JPEG…）、颜色模式/深度、Cycles 采样、EEVEE 采样等 |
| 帧号 | 快照录制时的当前帧，渲染时切回该帧 |

批量渲染：

- 点击渲染后插件保存当前场景副本（含未保存修改），启动 `blender -b`
  子进程逐个应用快照并渲染；主进程用 `bpy.app.timers` 轮询进度，面板显示
  进度条/当前快照/完成计数。
- **勾选渲染**：每个快照前有勾选图标按钮（默认全勾），「渲染勾选」只渲染
  勾选的快照、与状态无关；列表上方提供「全选 / 全不选 / 反选」快捷操作。
- **UI 完全可操作**：渲染期间可继续建模、切换场景；点「停止渲染」可随时中断
  （被中断的当前张保持待渲染状态，可稍后重跑）。
- 单张渲染失败、被取消或写盘失败时，该快照标记为「失败」继续下一个，
  不会被误标为完成。
- **快照按场景独立存储**：快照列表挂在每个 Scene 数据块上（官方文档推荐
  的 per-scene 方式），切换场景后面板显示的是该场景自己的快照；「清空全部
  快照」可一键删除当前场景的所有快照（带二次确认，防误删）。
- 每次渲染在输出目录生成 `rm_render_log_*.txt` 日志（含快照版本与视图层
  验证结果），失败时面板消息会给出日志路径。
- **实时进度**：渲染中面板实时显示当前张的采样数（如 `采样 80/400`）、
  已用时间与 Blender 预计的剩余时间（来自 Cycles 渲染统计，每 0.5 秒刷新）。
  **进度条采用 Blender 引擎的整体渲染进度**（已完成像素 / 总像素：由分辨率
  与「平铺尺寸」计算每块像素占比，块大小不均时进度同样准确，随块与采样平滑
  推进、块完成瞬间不跳变），采样数与块数以文本显示（如 `采样 128/128 ·
  块 2/4`）；全部块完成后显示「收尾中…」（去噪/合成/保存阶段，属正常现象）。
- 输出文件自动命名（见下文模板），不会覆盖。

## 安装

1. 使用项目根目录的 `render_monitor.zip`。该包是标准 **Blender 扩展包**（内含
   `blender_manifest.toml`），zip 内第一层是 `render_monitor/` 文件夹：
   - **Blender 4.2+（推荐）**：直接把 zip **拖进 Blender 窗口**即可安装
     （也可 `Edit → Preferences → Get Extensions → 右上角下拉菜单 →
     Install from Disk` 选择该 zip）；拖入新版本 zip 可直接覆盖更新。
     最低支持 Blender 4.2.0。
2. 在插件/扩展列表勾选启用 **“Render Monitor 渲染监视器”**（分类 Render）。
3. 若需手动打包：进入项目根目录，把整个 `render_monitor` 文件夹压缩，
   确保 zip 打开后第一层是 `render_monitor/`（内含 `__init__.py` 与
   `blender_manifest.toml`），而不是散落的 `.py` 文件。

## 使用

在 3D 视图按 `N` 打开侧边栏，找到 **Render Monitor** 标签页：

1. **捕获快照**：摆好一版场景（物体可见性/变换、集合开关、环境、相机、
   渲染设置、帧号）后点「捕获快照」，可命名。重复此步骤得到多个快照，
   新快照默认名统一为「快照」。
2. 用列表右侧的上/下箭头调整渲染顺序（顺序即文件编号；列表每项前的
   数字序号就是该编号，便于和输出文件名对照）；双击列表项可重命名。
3. **输出目录**默认是当前 .blend 文件所在目录（`//`）；若文件尚未保存，
   点击渲染时会弹出对话框让你选择输出目录（绝对路径）。
4. 用每个快照前的勾选图标挑选要渲染的（默认全勾），或点列表上方的
   「全选 / 全不选 / 反选」批量设置；点「渲染勾选（勾选数/总数）」渲染所有
   **勾选**的快照，「渲染当前」只渲染列表中高亮的那一张。渲染为后台执行：UI 不冻结，
   面板会显示进度条、当前渲染的快照名和完成计数；点「停止渲染」可随时中断
   （被中断的当前张保持待渲染状态，可稍后重跑）。
5. 渲染中面板还会实时显示当前张的**采样数、已用时间、预计剩余时间**
   （来自 Cycles 渲染统计；非 Cycles 引擎或统计不可用时显示 `—`）。

### 文件命名模板

支持三个占位符：

- `{name}` — 快照名称（自动清洗非法字符）
- `{index}` — 快照在列表中的顺序编号，从 1 开始（如 1、2、3），
  可带格式如 `{index:02d}` → `01`
- `{frame}` — 渲染帧号，可带格式如 `{frame:04d}` → `0007`

默认模板 `{name} {index}`：快照名统一为「快照」时，三个快照输出为
`快照_1.png`、`快照_2.png`、`快照_3.png`（空格自动转为下划线）。
模板若不含任何占位符会自动回退默认模板，避免互相覆盖。

### 其他选项

- **渲染勾选**（列表每项前勾选图标，默认全勾）：批量渲染只渲染勾选的快照，
  与状态无关（已完成/失败/待渲染勾选后都会渲染）；列表上方提供
  「全选 / 全不选 / 反选」快捷设置。勾选状态随 .blend 文件保存。
- **使用快照帧**：渲染时切到快照记录的帧号（默认开启）。
- **输出渲染日志**：默认关闭；排查问题时勾选，渲染后输出目录会生成
  `rm_render_log_*.txt`（含快照版本、视图层验证结果与子进程输出）。

## 后台渲染机制（为什么不卡 UI）

`bpy.ops.render.render()` 从 Python 脚本调用会**阻塞主线程**（UI 冻结），
这是 Blender 的固有行为，插件无法绕过。因此本插件改用**独立子进程渲染**：

1. 点击渲染后，插件把当前场景状态保存为一份**临时副本**（`copy=True`，
   包含你尚未保存的修改，不影响当前文件）；
2. 用 `bpy.app.binary_path` 自动找到的 blender 可执行文件启动
   `blender -b` 后台子进程，在**子进程**里逐个应用快照并渲染；
3. 主进程用 `bpy.app.timers` 每 0.5 秒轮询子进程的进度文件，更新面板
   的进度条和快照状态；
4. 渲染期间 UI **完全可操作**（可继续建模、切换场景、看进度）；
   点「停止渲染」或渲染完成时，插件清理临时副本。

好处：主场景**从头到尾零修改**，不存在“渲染后恢复”的副作用；
渲染失败/崩溃也不影响当前工作。代价：每批渲染多一次保存副本和
子进程启动的开销（数秒）。

## 已知限制

- **复制场景会复制快照**：用 Blender 的「复制设置 / 链接复制 / 完整复制」
  新建场景时，快照列表会随场景设置一并复制到新场景（这是 Blender 原生行为，
  不是共享——之后两边的快照互不影响）。新场景如需从零开始，用「清空全部
  快照」一键删除即可；「新建」（空场景）不会复制快照。
- **渲染期间不要修改快照列表**：渲染队列在启动时已导出，期间对快照的
  修改（含勾选状态）不会影响本次渲染（下次渲染生效）。
- **未保存的文件**：可以渲染，但输出目录必须是绝对路径（点击渲染时
  会弹窗让你选择）；`save_as_mainfile(copy=True)` 会把当前未保存状态
  写入副本，不影响主场景。
- **快照按对象/集合名称引用**：改名后快照应用会找不到对应对象（静默跳过）。
- Blender 5.0 起 `World.use_nodes` 已废弃（恒为开启），插件不再依赖该开关
  恢复环境；背景节点（Background）的颜色/强度仍会恢复，自定义的复杂环境
  节点树（如天空纹理）不会逐节点恢复。
- 有**约束（constraint）**的物体：恢复变换后约束会重新计算并覆盖，可能与
  快照时的姿态不完全一致（建议对纯静态摆位场景使用）。
- 渲染设置按“路径+值”动态记录，属性在目标引擎下不存在时自动跳过
  （如 Cycles 采样项在 EEVEE 下无效）。
- 快照数据随 .blend 文件保存（存放在 `data_json` 属性中），换机器/改名后
  引用失效。

## 开发

```
# 运行单元测试（纯逻辑 + mock bpy 的捕获/恢复往返测试，不需要启动 Blender）
python -m unittest discover -s render_monitor/tests -t .
```

代码结构：

```
render_monitor/
├── __init__.py   # 入口：bl_info、属性、注册
├── core.py       # 快照捕获/恢复（依赖 bpy，可 mock 测试）
├── ops.py        # 操作符：快照管理 + 子进程渲染与会话管理
├── rm_job.py     # 子进程渲染脚本（blender -b 后台执行）
├── ui.py         # N 面板 + UIList + 进度条
├── utils.py      # 纯逻辑：文件名清洗/模板/路径（可独立测试）
└── tests/        # unittest
```

## 兼容性

目标版本 **Blender 5.2**（`bl_info["blender"] = (5, 2, 0)`）。渲染设置使用
动态容错存取，在 Blender 4.x 的大部分属性上也兼容，但未在 4.x 上验证。

## 版本历史

- **v1.4.6**：列表序号列宽度改为随最大序号位数自适应（1 位≈0.7u、
  2 位≈1.0u、3 位≈1.3u……），修复 100+ 项时 3 位数序号被截断成省略号
  的问题，位数少时列宽也不浪费。
- **v1.4.5**：数据保护审计修复——①渲染不再预先删除同路径旧输出文件：
  改为渲染到唯一临时文件、成功后原子替换（`os.replace`），渲染失败/取消时
  上一次成功渲染的图片原样保留（此前会先删旧文件，渲染失败即永久丢失）；
  ②「清空已完成」增加二次确认（与「清空全部」一致），防误删不可恢复的
  快照数据。新增对应回归测试。
- **v1.4.4**：修复恶性 bug——未启用（exclude/隐藏）的集合里的物体，
  应用快照后位置/旋转归零。根因：对象变换此前用 `matrix_local` 记录，
  而它是依赖图评估的缓存结果，对象在 exclude/隐藏集合时依赖图不评估它，
  读取得到默认单位矩阵。改为记录/恢复对象直接数据
  `location` / `rotation`（含 Euler/Quaternion/AxisAngle） / `scale`
  （含 delta 变换），任何集合状态下都可靠；旧快照（v1/v2）自动回退
  `matrix_local`，快照格式升级为 v3。
- **v1.4.3**：快照列表序号列固定宽度并右对齐——此前 label 按文本取宽，
  序号 1~9 与 10+ 宽度不同导致已完成/待渲染各行横向错位，且列显宽。
- **v1.4.2**：修复列表仍不显示的 bug——`row.label()` 不支持 `emboss`
  参数（该参数仅 prop/operator 可用），已移除；并逐行审查全部
  UILayout 调用确保参数合法。
- **v1.4.1**：修复列表序号导致列表不显示的 bug——`draw_item` 中误把
  UIList 的 `data` 参数（scene）当集合遍历，改为取 `data.rm_shots`，
  并加异常兜底保证列表渲染永不中断。
- **v1.4.0**：快照列表每项新增渲染勾选（勾选图标按钮，默认全勾）——
  「渲染勾选」按钮只渲染勾选的快照（按钮上显示勾选数/总数），取消
  「仅渲染未完成」选项；新增「全选 / 全不选 /
  反选」快捷按钮；勾选状态随 .blend 文件保存，
  上下移/调整顺序时保留勾选；环境诊断的插件版本改为读取
  blender_manifest.toml（修复扩展模式下模块 bl_info 被忽略导致版本显示"?"的问题）。
- **v1.3.3**：修复 `{index}` 文件编号 bug——批量渲染（含「仅渲染未完成」
  过滤）与单张渲染时，编号改取快照在列表中的**原始顺序**（从 1 开始），
  不再按本次渲染队列重新计数。此前中断后续跑会从 1 重排编号，导致文件名
  错乱并覆盖已渲染文件。
- **v1.3.0**：快照确认按场景独立存储（per-scene，符合官方文档）；面板顶部
  显示当前场景名与快照数，方便多场景下区分；新增「清空全部快照」（一键删除
  当前场景全部快照，带二次确认，复制场景后清理旧快照很方便）。
- **v1.2.0**：渲染中面板实时显示当前张的采样数、已用时间与预计剩余时间
